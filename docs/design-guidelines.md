## 1. 사용 환경과 사용자

| 항목 | 내용 | 상태 | 이유 |
|---|---|---|---|
| 사용자 | 고령자. 혼자 서서 쓴다 | 확정 | 과제 목표가 고령자 안내 (`CLAUDE.md`) |
| 장소 | 버스정류장, 지하철역 | 확정 | 키오스크 설치 장소 (`CLAUDE.md`) |
| 하는 일 | 목적지를 말하거나 골라서 대중교통 경로를 본다 | 확정 | `docs/kiosk-workflow.md` |
| 입력 | 터치(탭)와 음성. 키보드·마우스 없음 | 확정 | 키오스크 기기 |
| 캔버스 | 1920×1080 가로 고정. 반응형 없이 무대(Stage) 배율로 화면에 맞춘다 | 확정 (2026-11-16 변경. 전에는 세로 1080×1920) | 시연 기기가 가로 모니터와 프로젝터다. 세로 무대는 가로 화면에서 56%로 줄어 작게 보이고, 세로 화면은 가운데 흰 바탕이 너무 넓었다 |
| 실물 기기 | 32인치 가로형으로 가정 | 임시 | 기기가 아직 없다. 실물 기기가 세로로 정해지면 배치(6절)만 다시 잡는다. 토큰·하한선·시선 순서는 그대로 쓴다 |
| 실제 크기 | 1px ≈ 0.37mm → 30px ≈ 11mm, 36px ≈ 13mm, 48px ≈ 18mm, 112px ≈ 41mm | 임시 | 32인치 16:9 패널에 1920×1080 을 꽉 채운다고 가정한 계산값 (방향이 바뀌어도 1px 크기는 같다) |

무대는 가로로 맞췄다. 화면 배치는 아직 세로로 쌓는 예전 구조다 (`frontend/src/components/Stage.jsx`. 6절의 좌우 두 칸과 8절의 첫 화면·띠는 아직 `frontend/` 에 옮기지 않았다. 예외: 2026-11-19 부터 LISTENING 은 얇은 띠 + 좌우 두 칸 새 틀 `components/FlowFrame.jsx`). `design/audit.md` 와 시안 v1~v4 는 세로 기준 기록이다.

밝기·햇빛 반사·설치 높이·보는 거리는 기기와 설치 장소가 정해지지 않아 **미확인**이다. 이 문서의 크기는 그 값 없이 정했다.

## 2. 반드시 지킬 하한선

| 규칙 | 상태 | 이유 |
|---|---|---|
| 글씨는 30px 이상 | 확정 | 가장 작은 글씨도 읽을 수 있어야 한다 |
| 버튼 높이는 112px 이상 | 확정 | 손가락으로 정확히 누르기 어려운 사용자를 위해 |
| 모든 글씨는 배경과 명도 대비 7:1 이상 | 확정 | WCAG 2.1 의 강화 대비 기준(1.4.6) 값을 가져왔다 |
| 조작은 탭만. 길게 누르기·끌기·두 손가락 동작 없음 | 확정 | 배워야 하는 동작을 없앤다 |
| 쓸 수 없는 버튼은 회색으로 두지 않고 숨긴다 | 확정 | 눌러도 반응 없는 버튼은 고장으로 보인다 |
| 아이콘만 있는 버튼 금지. 버튼에는 글자가 있다. 아이콘은 글자와 함께 쓴다 (3-7절) | 확정 | 아이콘 뜻을 추측하게 하지 않는다 |
| 주 버튼은 화면당 최대 1개 | 확정 | "다음에 누를 것"이 하나여야 한다 |
| 스크롤 없이 한 화면에 들어가게 설계. 스크롤은 안전장치로만 남긴다 | 확정 | 스크롤은 탭이 아닌 동작이다 |
| 페이지 넘김 버튼을 만들지 않는다 | 확정 | 버튼 종류·개수를 디자인 작업으로 늘리지 않는다 |
| 버튼 종류·개수·dispatch 이벤트는 디자인 작업으로 바꾸지 않는다 | 확정 | 상태 전이 표가 기준이다 (`docs/kiosk-workflow.md`) |

주 버튼 규칙의 의도된 예외 (확정, 버튼 구조를 바꾸지 않기 위해):
- 목록 버튼(`CONFIRMING` 후보, `MANUAL_SELECT` 목적지)은 묶음 전체를 주 버튼 하나로 센다. 고르는 카드 모양은 11-1절
- `CONFIRMING` 은 주 버튼('예' 또는 후보 목록)이 아래 버튼 영역이 아니라 본문에 있다
- `QR_HANDOFF` 는 주 버튼이 없고 보조 버튼 '처음으로' 하나뿐이다
- `ROUTE_GUIDE`의 경로 카드(최대 3개)는 고르는 버튼이다. 주 버튼으로 세지 않는다. 이 화면의 주 버튼은 '휴대폰으로 보내기' 하나다. 카드도 높이 112px 이상, 글씨 30px 이상을 지킨다 (2026-11-17, 팀장 요청으로 추가한 버튼. 2026-11-19 확정)

목록 기준 개수 (확정): 후보 최대 3개(`stt/api.py` `collapse(k=3)`), 목적지 최대 12개(`stt/api.py` `/pois` 기본 `limit=12`). 목적지는 왼쪽 칸에 3열 4줄, 후보는 왼쪽 칸에 1열로 설계한다 (6절).

### 3-2. 글씨·배경 허용 조합 (명도 대비)

WCAG 2.1 계산식으로 직접 계산했다: 대비 = (L1 + 0.05) / (L2 + 0.05), L 은 sRGB 상대 휘도, L1 이 밝은 쪽.
이 표에 없는 조합은 쓰지 않는다. 새 조합이 필요하면 계산해서 이 표부터 고친다.

|---|---|---|---|---|
| 본문 `#111111` | 18.88 | 16.87 | 16.73 | 15.13 |
| 보조 `#444444` | 9.74 | 8.70 | 8.63 | 7.80 |
| 오류 `#8C1D18` | 9.11 | 8.14 | 8.07 | 7.30 |
| 파랑 `#0A4A9F` | 8.42 | 7.52 | 7.46 | **6.75 미달** |

| 글씨 \ 배경 | 주 버튼 `#0A4A9F` | 주 버튼 눌림 `#083A7D` | 머리말 띠 `#111111` |
|---|---|---|---|
| 흰색 `#FFFFFF` | 8.42 | 10.99 | 18.88 |

- **기준 미달 1건**: 파랑 글씨 + 보조 눌림 배경(6.75:1). 이 조합은 금지한다. 지금 화면에는 파랑 글씨가 없어서 해당하는 곳이 없다
- 그 밖의 조합은 모두 7:1 이상이다. 가장 낮은 값은 오류 글씨 + 보조 눌림 배경 7.30:1
- 주 버튼 배경 위에는 흰 글씨만 올린다 (확정)
- 머리말 띠 배경 위에도 흰 글씨만 올린다 (확정). 띠는 누르는 것이 아니다
- 선택된 경로 카드: 강조 배경 `#EAF2FC` + 주 색 `#0A4A9F` 테두리. 글씨는 본문색·보조색 그대로다 (16.73, 8.63). 고르지 않은 카드: 흰 배경 + 보조색 테두리. 새 색은 없다. 선택 여부를 색에만 맡기지 않고 테두리 굵기(6px)와 카드 왼쪽의 체크 아이콘을 함께 쓴다 (2026-11-17 변경. 전에는 "선택됨" 글자)

경로 안내(`ROUTE_GUIDE`)의 노선 표시 (확정, 2026-11-17):
- 지하철은 동그라미 안에 노선 번호, 버스는 둥근 네모 안에 버스 번호만 쓴다. "간선", "지선" 같은 종류 글자는 쓰지 않는다. 종류는 테두리 색(버스 종류 색)으로만 보인다
- 둘 다 흰 바탕 + 노선색(버스 종류 색) 6px 테두리 + 검정 글씨, 높이 52px. 모양이 달라서 색을 못 봐도 지하철과 버스가 구별된다
- 번호 글씨는 둘 다 30px 굵기 400 이다(IDLE 띠의 노선 원, QR 단계 번호와 같다) (2026-11-19. 전에는 버스 번호만 700)
- 경로 카드·요약 판에서 탈것 사이의 화살표(→)는 28px, 선 3px 이다. 아이콘이 아니라 노선 표지(테두리 6px) 사이의 기호라서 노선 표지의 굵기에 맞췄다. 3-7절의 아이콘 선 굵기(152px 에서 9.5px)를 따르지 않는다 (2026-11-19)
- 타임라인의 구간 줄은 노선 표시(노선 원 또는 버스 번호 네모) 옆에 한 줄만 쓴다: "N번째 역에서 내려요", 1이면 "다음 역에서 내려요". 버스는 "N번째 정류장에서 내려요", "다음 정류장에서 내려요". 타는 역은 세지 않는다 (2026-11-17 변경. "2정거장"은 세는 법이 애매했고, 지나는 역 이름 줄은 정보가 너무 많았다)

- 버스 번호는 한 줄이고 자르거나 줄이지 않는다("9401-1" 도 그대로). 카드의 노선 줄이 소요 시간 옆에 안 들어가면 둘째 줄로 내리고, 도착 시각을 소요 시간 옆으로 옮긴다

- 타는 방향("이 정류장에서 타세요" / "길 건너편 정류장에서 타세요")은 화면에 보이지 않는다 (2026-11-17 변경). 데이터 형식에는 선택 항목으로 남긴다

### 3-9. 시선 순서

화면을 3초 봤을 때 눈이 가는 순서를 정해 둔다 (확정, 2026-11-16). 첫 화면 기준:

**1순위 주 버튼 → 2순위 큰 질문 → 3순위 예시 문구 → 4순위 노선 그림과 그 밖의 정보**

| 규칙 | 이유 |
|---|---|
| 화면에서 진하게 채운 색 덩어리는 주 버튼 하나뿐이다. 검은 판·진한 띠를 두지 않는다 | 다음에 누를 것이 가장 먼저 보여야 한다 |
| 큰 질문은 주 버튼 바로 위에 붙여 한 덩어리로 보이게 한다 | 읽을 것과 누를 것을 가깝게 (`design/audit.md` 공통 문제 3번) |
| 예시 문구는 옅은 바탕이나 테두리 없는 글자로 둔다 | 3순위가 1순위와 다투지 않게 |
| 덜 눈에 띄어야 하는 글씨는 색을 연하게 하지 않고 크기와 굵기를 줄인다 | 대비 7:1 과 30px 하한선을 지키면서 순서를 만든다 |
| 확인 방법: 스크린샷을 흐리게(blur 12px), 흑백으로, 1/4 로 줄여서 본다. 세 경우 모두 주 버튼이 가장 먼저 보여야 한다 | 느낌이 아니라 그림으로 확인한다 |
| 흐린 그림은 화면마다 반드시 열어서 본다. 비슷할 것이라고 짐작해서 통과로 적지 않는다 | 보지 않은 것을 봤다고 적으면 검사가 아니다 (2026-11-16 추가) |
| 그림과 함께 숫자 세 가지를 보고한다: ① 주 버튼이 화면 넓이에서 차지하는 비율(%) ② 화면에서 가장 큰 글씨와 주 버튼 글씨의 크기 ③ 어느 칸이나 띠에도 속하지 않고 흰 바탕에 놓인 요소의 수 | 흐림 검사만으로는 "버튼이 강조되지 않는다", "그림이 떠 있다"를 잡지 못했다 (2026-11-16 추가) |

- 의도한 예외 (2026-11-18, 팀장): 무입력 화면 6개(`CONFIRMING`, `REASKING`, `UNAVAILABLE`, `MANUAL_SELECT`, `ROUTE_GUIDE`, `QR_HANDOFF`)에서 남은 시간이 15초 이하일 때 얇은 띠 오른쪽(날짜·시각 자리)에 나오는 남은 시간 알림 판(`--color-band` 바탕 + 흰 글씨)은, 보이는 15초 동안 화면에서 가장 진한 덩어리가 된다. 곧 처음으로 돌아간다는 것을 먼저 알려야 하므로 이때만 주 버튼·1순위보다 먼저 보여도 된다. 알림이 없을 때의 시선 순서는 그대로다 (11-4절)
- 머리말 띠(`--color-band`, 3-1절)는 진한 덩어리라서 주 버튼이 있는 화면에서는 이 규칙과 부딪힌다. 시안 v4 는 띠를 쓰지 않는다. 띠를 계속 쓸지는 나머지 화면을 만들 때 정한다
- 띠의 역·정류장 이름(112px 굵게)은 흐린 그림에서 질문(96px)과 비슷하게 보이고, 이름이 긴 버스정류장("종로3가.탑골공원")에서는 질문보다 먼저 보인다. 주 버튼은 모든 화면에서 가장 먼저 보인다. 이름을 굵게 두는 것과 IDLE_REDUCED 의 질문 96px 은 이 점을 알고 정했다 (2026-11-17, 팀장)

## 6. 배치: 좌우 두 칸 (가로 캔버스)

1920×1080 에서 바깥 여백 48px 을 빼면 쓸 수 있는 영역은 1824×984px 이다. 모든 화면을 좌우 두 칸으로 나눈다 (확정, 2026-11-16).

| 칸 | 너비 | 들어가는 것 |
|---|---|---|
| 왼쪽 | 1068px (x 140px 에서 오른쪽 칸 앞 64px 까지. 2026-11-18 변경, 전에는 x 48px 에서 1160px) | 이 화면의 내용: 머리말, 그림, 질문, 안내, 고를 목록(목적지, 후보), 후보가 1개일 때의 '예' 버튼 |
| 사이 | 64px | 비운다 |
| 오른쪽 | 600px | 공통 행동 버튼. 세로 한 줄, 칸의 아래쪽에 붙인다. 주 버튼이 있으면 맨 위 |

- '처음으로'는 모든 화면에서 오른쪽 칸 맨 아래, 같은 자리에 둔다
- 오른쪽 칸에는 판을 깔지 않는다. 배경은 위쪽 띠(`--color-bg-group`)와 본문(흰색) 두 가지뿐이다 (2026-11-17 변경. 전에는 "옅은 판으로 깐다"였다)
- 첫 화면(IDLE, IDLE_REDUCED)은 예외로 버튼 칸이 740px 이고 큰 띠를 쓴다 (8절). 아래 계산표는 그 밖의 화면, 얇은 띠(96px) 기준이다
- `ROUTE_GUIDE` 왼쪽 칸: 제목과 선택된 경로의 타임라인(역 이름, 노선 번호 원과 정거장 수, 갈아타는 곳의 걷는 시간, 내리는 역의 출구 번호). 시안에서는 맨 아래에 "예시" 안내 한 줄 (2026-11-17 변경)
- `ROUTE_GUIDE` 오른쪽 칸: 경로 카드 3개를 세로로 쌓는다. 카드가 요약을 겸한다(소요 시간과 노선 번호 원, 선택된 카드에만 도착 시각). 그 아래 휴대폰으로 보내기 / 처음으로. 같은 정보는 화면에 한 번만 보인다 (2026-11-17 변경) 확정 (2026-11-17, 팀장)
- `ROUTE_GUIDE` 경로가 1개면 카드 대신 요약 판(버튼 아님)을 두고, 요약 판과 버튼을 한 묶음으로 칸 아래쪽에 붙인다. 위쪽은 비워 둔다 (9절 R3)
- 버튼이 없는 기다림 화면 5개(`STARTUP_CHECK`, `CHECKING`, `RESOLVING`, `ROUTING`, `FAIL_COUNT_CHECK`)는 좌우 두 칸을 쓰지 않는다. 화면 가운데에 세로로: 고리 → 작은 머리말(있을 때만) → 큰 글씨(112px) → 안내 한 줄(48px) (2026-11-17) (10절)
- 왼쪽 칸은 모든 화면에서 x 140px 에서 시작한다(IDLE 질문 묶음과 같은 세로선, `design/mockups/shared/flow.css`). 바깥 여백 48px 과의 사이 92px 은 비운다. 140 + 1068 + 64 + 600 + 48 = 1920 (2026-11-18, 팀장)
- 목록 열 수: 목적지(`MANUAL_SELECT`)는 왼쪽 칸에 3열 4줄(한 칸 (1068 − 20×2) ÷ 3 ≈ 343px. 2026-11-18 변경, 전에는 373px), 후보(`CONFIRMING`)는 왼쪽 칸에 1열

## 8. 첫 화면과 띠 (확정, 2026-11-17)

확정 시안은 `design/mockups/confirmed/` 의 `idle-final-subway.html`, `idle-final-bus.html`, `idle-final-default.html`, `idle-reduced-final.html`, `band-thin.html` 이다. `frontend/` 에 옮겼다 (2026-11-19, 옮기기 계획 7단계: `components/PlaceBand.jsx`, `IdleFrame.jsx`, `IdleButtons.jsx`, 규칙은 `view/placeBand.js`). 띠 이름(끝의 "역"·"정류장" 떼기)은 얇은 띠도 같은 함수(`view/placeName.js`)를 쓴다. 장소 정보(`place`)가 없어도 위치 응답에 이름(`name`)이 있으면 얇은 띠는 그 이름을 같은 규칙으로 보인다(종류를 모르면 이름 끝이 "역"·"정류장"일 때만 뗀다). 이름 끝에 " 키오스크"가 붙어 오면(서버의 고정 위치 이름, 예: "종로3가역 키오스크") 그것을 먼저 떼고 그다음 "역"·"정류장"을 뗀다: "종로3가역 키오스크" → "종로3가" (2026-11-20). 이름도 없을 때만 비운다. 큰 띠는 장소 정보가 없으면 지금처럼 "정보 없음" 모양이고, 이름만 있는 큰 띠는 만들지 않는다 (2026-11-20).

### 8-1. 화면의 구역

- 배경은 두 가지뿐이다: 위쪽 띠(`--color-bg-group`)와 그 아래 본문(흰색). 띠와 본문은 바탕색 차이만으로 나눈다. 테두리 선이나 그림자를 더하지 않는다
- 큰 띠(높이 337px)는 첫 화면(IDLE, IDLE_REDUCED)에만 쓴다. 역명판을 본뜬 띠이고 "지금 계신 곳" 표시를 겸한다
- 그 밖의 화면은 얇은 띠(높이 96px)를 쓴다: 로고, 가운데에 지금 계신 곳 이름(흰 판 없이 글자만, 48px 굵게), 오른쪽에 날짜와 시각
- 이유: 큰 띠를 그대로 쓰면 본문에 남는 높이(671px)에 `MANUAL_SELECT`(747px)와 환승 2회 경로가 들어가지 않는다

### 8-3. 큰 띠의 모양

- 위쪽 줄: 로고와 서비스 이름(왼쪽), 날짜와 시각(오른쪽). 높이 96px 줄의 세로 가운데에 놓아 얇은 띠와 같은 자리다(로고 y 26, 날짜·시각 글자 y 30). IDLE 에서 다음 화면으로 넘어갈 때 로고와 시각이 움직이지 않는다 (2026-11-19. 전에는 2px 위)
- 가운데 이름 상자: 흰 바탕, 둥근 모서리(20px), 그림자 없음. 화면 가로 가운데. 이름은 112px 굵게, 한 줄 (7절)
- 노선 선: 굵기 14px, 화면 왼쪽 끝에서 오른쪽 끝까지 이름 상자 뒤로 이어진다
- 선 위의 글자는 흰 표지(테두리 없음, 모서리 4px) 안에 검정으로 쓴다. 노선색 위에 글자를 직접 올리지 않는다 (3-6절)
- 지하철역: 줄마다 왼쪽에 노선 번호 원과 앞 역, 오른쪽에 다음 역. 앞뒤 역은 노선 수와 상관없이 한쪽에 하나씩이다
- 버스정류장: 줄마다 왼쪽에 버스 종류, 오른쪽에 번호(흰 표지에 하나씩)
- 장소 정보가 없으면: 회색 선 세 줄과 "지금 계신 곳을 확인하고 있어요" (위치 응답에 이름만 있어도 큰 띠는 이 모양이다. 얇은 띠는 이름을 보인다)

| R1 | 환승 2회 이하 경로만 보인다(최대 3개). 그런 경로가 없으면 환승이 가장 적은 경로 하나를 요약 판으로 보이고 R2를 끝까지 쓴다 |

역 라벨 정리: 첫 점 "타는 곳"(먼저 걸어가면 "지금 계신 곳"), 다음 차를 타는 곳 "갈아타는 곳", 마지막 차에서 내리는 곳 "내리는 곳", 장소 목적지 "가실 곳".

첫 점 이름에 지금 계신 곳(위치 응답의 이름)을 쓸 때는 끝의 " 키오스크"만 떼고 "역"·"정류장"은 남긴다: "종로3가역 키오스크" → "종로3가역". 타임라인에는 띠의 선·표지가 없어 역인지 정류장인지 이름으로 알려야 한다. 띠 이름은 7절 규칙 2대로 "종로3가"다 (2026-11-20, `view/placeName.js` `startPlaceName`)

왼쪽 칸 맨 아래의 예시 안내("버스 번호, 시간, 출구는 예시예요" / 버스가 없으면 "시간과 출구는 예시예요")는 시안 전용이다. 실제 앱에는 넣지 않는다. 그래서 앱의 타임라인 칸은 시안보다 그 줄만큼(약 58px) 길고, R2 줄이기는 덜 줄일 수 있다 (2026-11-20 팀장 확인, 그대로 둔다). 시안의 `?case=transfer3` 은 ① → ② → ④ 인데 앱은 ① → ④, `?case=longcard`·`?case=longthree` 는 시안 ① 인데 앱은 줄이지 않는다. 안내 줄을 뺀 시안과는 15가지 경우가 모두 같다

시안에서 확인한 것: 탈것 3개가 모두 긴 이름(공항철도 → 9401-1 → 경의중앙선)이어도 카드 노선 줄이 두 줄에 들어간다(표지 사이 간격은 줄이지 않았다). 소요 시간이 세 자리(100분 이상)인 경우는 찍어 보지 않았다.

## 10. LISTENING과 기다림 화면 (확정 2026-11-17)

확정 시안은 `design/mockups/confirmed/listening-final.html`, `wait-final.html`(`wait.css`)이다. LISTENING 은 `frontend/` 에 옮겼다(2026-11-19, 옮기기 계획 2단계. 음량 막대는 가짜 음량, 실제 음량은 12단계). 기다림 화면 5개도 옮겼다(2026-11-19, 옮기기 계획 3단계. `components/WaitFrame.jsx`, 글씨 줄이기는 `hooks/useFitText.js`). 72px 까지 줄여도 넘치는 글은 아래 10-2절 규칙으로 줄을 바꾼다.

### 10-1. LISTENING

- 배경은 흰색으로 확정한다. 옅은 파랑 안은 쓰지 않는다
- 왼쪽 칸에 듣는 중 표시 640px(고리 + 마이크 + 음량 막대 40개)와 "듣고 있어요", 오른쪽 칸에 다 말했어요 / 취소 / 처음으로를 둔다 (실제 마이크 모드, 글 입력창 없음)
- 화면 제목은 없다. 실제 앱의 제목 "말씀해 주세요"는 "듣고 있어요"와 뜻이 겹쳐서 뺐고, "듣고 있어요"(72px 굵게)가 제목 역할을 한다 (시안 v2 부터, `design/mockups/README.md` v2 절. 2026-11-19 이 절에 옮겨 적음). 버튼의 종류·개수·문구는 그대로다

### 10-2. 기다림 화면 공통 배치 (STARTUP_CHECK, CHECKING, RESOLVING, ROUTING, FAIL_COUNT_CHECK)

- 얇은 띠 아래, 화면 가운데에 세로로 고리 → 작은 머리말(있을 때만, 30px) → 큰 글씨(112px 굵게, 넘치면 8px씩 72px까지) → 안내 한 줄(48px)을 놓는다. 버튼 칸은 두지 않는다
- 고리는 LISTENING과 같은 토큰(`--halo-r`, `--ring-r`, `--ring-icon`)으로 그린다. 고리 가운데 높이도 LISTENING과 같다(화면 위에서 495px)
- 바깥 고리 위를 주 색 호 하나가 `--motion-wait`(1.6s)에 한 바퀴 돈다. 움직임 줄이기 설정에서는 멈춘다
- **72px 로도 넘치는 긴 글** (확정 2026-11-19, 팀장): 72px 에서 줄을 바꿔 최대 3줄까지 보인다. 줄 길이는 고르게 나눈다(6절 카드 이름 줄 바꿈 규칙과 같다: 띄어쓰기가 있으면 띄어쓰기에서만, 한 단어면 글자 사이에서, 둘 다 `text-wrap: balance`). 말줄임표로 자르지 않는다. 3줄을 넘는 글은 오지 않는다고 보고 따로 줄이지 않는다(넘치면 4줄째도 보인다. 실제 길이는 `docs/team-requests.md` #14). 구현은 `hooks/useFitText.js` 의 `wrapAtMin`. 같은 규칙을 REASKING 의 "잘 못 알아들었어요"·들은 말, UNAVAILABLE 의 이유 문장에도 쓴다(12-2·12-3절)

### 10-3. 화면별 가운데 그림과 글씨 (문구는 실제 화면 그대로)

| 화면 | 가운데 그림 | 머리말 / 큰 글씨 / 안내 |
|---|---|---|
| ROUTING | 깃발 | 가실 곳 / 목적지 이름 / 가는 길을 찾고 있어요 |
| RESOLVING | 말풍선 | 들은 말 / "병원"(따옴표 포함) / 말씀을 알아듣는 중이에요 |
| STARTUP_CHECK | 서비스 로고 | 없음 / 준비하고 있어요 / 잠시만 기다려 주세요 |
| FAIL_COUNT_CHECK | 말풍선 | 없음 / 잠시만요 / 확인하고 있어요 |
| CHECKING | 남은 초(120px, 숫자 폭 고정) | 없음 / 잠시만 기다려 주세요 / 잠시 문제가 생겼어요. N초 뒤에 다시 해 볼게요 |

- 가운데 그림은 IDLE·LISTENING 아이콘과 같은 선 굵기로 그린다(152px에서 9.5px). 로고도 이 굵기로 다시 그려서 띠의 로고보다 선이 가늘다
- CHECKING은 호가 돌지 않고 남은 시간만큼 줄어든다. 움직임 줄이기 설정에서는 1초에 한 번만 줄어든다. 오류 색은 쓰지 않는다
- RESOLVING에서 들은 말이 비어 있으면: 머리말과 안내 줄을 빼고, 큰 글씨 자리에 "말씀을 알아듣는 중이에요"를 둔다. 이 경우는 실제로 생긴다: LISTENING에서 10초 동안 말이 없으면 빈 텍스트로 `SPEECH_END`를 보내 RESOLVING으로 온다(`docs/kiosk-workflow.md` 전이 표 `LISTENING → RESOLVING`, `frontend/src/screens/ResolvingScreen.jsx` 가 이때 '들은 말' 줄을 숨긴다). 시안은 `wait-final.html?s=RESOLVING&heard=`

### 10-4. 고리 위치가 LISTENING과 다른 이유

- LISTENING의 고리는 왼쪽 칸 가운데(x 460)이고, 기다림 화면의 고리는 화면 가운데(x 960)다. 높이는 같다
- 이렇게 정한 이유: LISTENING 바로 뒤에 오는 기다림 화면은 RESOLVING 하나뿐이고, 화면 전환이 밀기가 아니라 나타나기(250ms)라서 고리가 옆으로 미끄러지는 움직임으로 보이지 않는다. 버튼이 없는 화면은 가운데에 두는 편이 균형이 맞다
- 고리를 LISTENING과 같은 자리(왼쪽 칸 가운데)에 두고 큰 글씨를 그 아래, 오른쪽 칸을 비운 안(B안)을 확인용으로 만들어 시연 페이지에서 넘겨 보며 비교했다. 팀장이 A안(화면 가운데)으로 정했다 (2026-11-17). B안 파일은 지웠다

- **구현 시 코드 문구 변경 필요**: 단계 세 줄은 새 문구다. 실제 앱(`QrHandoffScreen.jsx`)은 "휴대폰 카메라로 QR을 찍으면 길 안내를 볼 수 있어요" 한 줄과 "(지금은 QR 대신 주소 글자로 보여 드려요)"를 보인다. 확정 시안은 단계 세 줄만 쓰고 괄호 문구는 뺐다

- QR 그림은 키오스크(브라우저)가 인터넷 없이 주소로 만든다: npm `qrcode-generator`(MIT, 오류 정정 M, 칸 수는 주소 길이에 맞춤). 서버가 그림을 줄지(`docs/team-requests.md` #10)가 정해지기 전의 대체 동작이다. 시안의 QR 은 예시 무늬(29칸)라 앱과 무늬·칸 수가 다르다. 상자 크기와 그림 크기(480px)는 같다 (2026-11-20)
- **QR 조용한 여백**: QR 무늬 둘레 흰 여백은 칸 4개 이상이어야 읽힌다(QR 규격). 그림 480px·여백 40px 이면 칸이 48개 이하일 때 여백이 4칸보다 모자란다(예: mock 주소 25칸 → 칸 19.2px, 여백 약 2.1칸). 그래서 흰 상자(560px)와 테두리는 그대로 두고, 상자 안쪽 560px 에 무늬와 여백을 함께 그린다: 여백 = max(4칸, 칸 수 ÷ 12칸)(= 40px 에 해당하는 칸 수). 칸이 48개 이하면 무늬가 480px 보다 작아지고(25칸 → 약 424px, 여백 약 68px), 넘으면 지금처럼 480px·여백 40px 이다. 시안의 예시 무늬(29칸, 여백 40px ≈ 2.4칸)와 무늬 크기가 다르다 (2026-11-20, 옮기기 계획 11단계)
- 휴대폰 주소가 없을 때(실제 서버가 `landing_url` 을 주지 않음. 새 경로 서버 `/routes/transit` 는 늘 없음, `docs/team-requests.md` #7·#15): 위 오류 상태 "QR을 만들지 못했어요" 를 보인다. 전이는 없고 '처음으로'로 나간다 (2026-11-20)
